# Auditor + rescue engine — roadmap to a "real" rescue bot

_Resume point as of 2026-05-17 19:10 UTC+2 (rev: 22:35 — proxy.upgradeTo v2 measured on full corpus)._
_HEAD on `origin/main` was `aa8b132` (`rescue-prove@5`); this doc landed in `fab5df6`._

> **2026-05-17 22:35 update — Tier-1 item #1 landed and measured.**
> The proxy-upgrade detection gap is **fixed**: `rules/core/proxy.upgradeTo_unprotected_v2.json` ships and produces **114 new critical findings on the existing 7,907-artifact corpus**, with **0 false positives** observed on a random 20-contract sample.
>
> The original `proxy.unprotected_implementation_upgrade.json` rule never fired because:
> 1. It demands `min_storage_role_confidence ≥ 0.9` and `min_path_reachability_confidence ≥ 0.85`. The Go builder hardcodes `path_reachability_confidence: 0.7` and the storage modeler returns `0.5` whenever the impl slot isn't a regular storage slot (which is ALWAYS — EIP-1967 is a magic-value slot, not slot 0/1/2).
> 2. Its `requires.storage_write.semantic_role_any: ["implementation"]` matcher iterates `state_model.slot_index` looking for a slot tagged `"implementation"`. The Go pipeline never tags a slot that way because EIP-1967 isn't modeled in `slot_index`.
> 3. Suppressors were a red herring — they never fired on the smallest candidate (`counter_evidence.suppressed_by: []`).
>
> v2 instead uses the **contract-level fact-match path** in `engine.go:384-418` and gates on `facts_all: ["ERC-1967", "PROXY_UPGRADE_SELECTORS"]` + `authorized_path_effect_any: ["delegatecall"]`. All three signals are already emitted by `knownbc.go` — so this is **pure rule JSON, zero Go code change**.
>
> **Empirical impact** (run against 168 dedup'd corpus candidates with both signals + <24KB bytecode):
> - 114 FIRED (67.9 %) — new critical-severity findings
> - 38 correctly suppressed (22.6 %) — 27 by OZ_ACCESS_CONTROL, 11 by OZ_OWNABLE2STEP
> - 16 lacked delegatecall (9.5 %) — correctly skipped (not actual UUPS implementations)
> - 0 errored
> - 0 false positives on 20 random non-proxy contracts
>
> Next: feed these 114 contracts into `rescue-prove` to see how many can also be drained.

> **2026-05-17 19:25 correction.** The initial v1 of this doc only proposed TypeScript/panel fixes for every Tier-1 item. That was wrong scope. Deep-inspection of `go/internal/decon/` revealed:
> - **The OOM is a 15-LOC fix in `stacksim.go`, not a wrapper-cap workaround.** Exponential string growth in symbolic `Expr` values is what hits 6+ GB on Uniswap V3 pools. The 8 GB cap I shipped masks this; it should be reverted once the proper fix lands.
> - **Bytecode detection of `upgradeTo` / ERC-1967 / reentrancy / initializer patterns is ALREADY done in `knownbc.go`** (lines 410-422, 468-470, 530-532). The signal IS reaching `global_tags`. The reason 0/3,613 findings exist is **rule suppressors triggered by mere admin-slot presence** (`knownbc.go:521-523` → rule's `suppress_if_any`).
> - **The detection problem is mostly fixable in rule JSONs + ~70 LOC of Go**, not a multi-day "rewrite the proxy resolver" effort.
>

## 2 · Roadmap (do these in order)

### Tier 1 — moves the needle the most

#### 1.1 · Resurrect proxy-upgrade detection ★★★★★
Either relax the existing rule's prerequisites OR ship a runtime-shortcut rule that doesn't require the Go auditor's broken proxy resolver.

**Cheapest path** — new rule `proxy.upgradeTo_unprotected_v2`:
- Fires when bytecode contains the `0x3659cfe6 upgradeTo(address)` or `0x4f1ef286 upgradeToAndCall(address,bytes)` selectors.
- Suppressors: presence of `onlyOwner` / `onlyAdmin` modifier proof, OR a `OZ_OWNABLE2STEP` fact, OR a 2-of-N timelock guard.
- Severity: `critical`; expected confidence 0.85 with selector witness alone.

**Why this unlocks more than a new rule** — it feeds the existing `init.public_initializer_takeover` path. Init-takeover → write attacker into admin slot → call `upgradeTo(attackerImpl)` → drain on next call. We already have rescue-prove plumbing for this (`buildAdminFanout`), starved of inputs.

Files to touch:
- `rules/core/proxy.upgradeTo_unprotected_v2.json` (new)
- `panel/src/server/sim/exploits/proxy-upgrade.ts` (new verifier — selector probe + suppressor check)
- Wire in `panel/src/server/sim/worker.ts` (`runSidecarVerifiers`)
- Bump `ENGINE_VERSION` → 10
- Backfill: `POST /api/proofs/backfill?limit=3613&onlyMissing=false`

Expected impact: **0 → 50–200 new findings** with clear drain shapes.

#### 1.2 · Approval-surface consent mode ★★★★★
Switch from scan-only to live drain when consenting victims exist.

Mechanics:
1. **Consent registry**: SQLite table `victim_consents (victim_address, contract_address, signed_message, signature, expires_at)`. EIP-712 typed-data signature; victim authorises a single rescuer EOA to call `transferFrom(victim, escrow, ≤ allowance)` once.
2. **Approval scanner** (per finding): `eth_getLogs Approval(_, contract, _)` over deployment-block → latest; group by victim; balance + allowance check.
3. **`RESCUE_APPROVAL_CONSENT_MODE=auto`**: rescue-prove emits a per-victim drain step gated by registry presence. Live broadcaster refuses any victim without a valid consent row.

Files to touch:
- `panel/src/server/sim/rescue-prove.ts` (replace stub at `// v3-A: scan-only mode`)
- `panel/src/server/rescue/consent-registry.ts` (new)
- `panel/app/api/rescue/consent/route.ts` (new — POST signed consent)
- UI: per-finding "victim consent status" panel

Expected impact: catches the entire approval-drain class (≈ unbounded $ surface — depends on victim signups).

#### 1.3 · Bytecode-level drain mining ★★★★
For every verified finding with priced exposure, enumerate **all** PUSHed function selectors (we already extract them in `decon`), call each with attacker-favoured calldata variants `(escrow, balance, max_uint, [escrow, escrow])`, pre-flight-prune the misses.

Files to touch:
- `panel/src/server/sim/rescue-prove.ts` — new builder `buildBytecodeSelectorFanout` (sibling of `buildEvidenceAdminFanout`).
- Cap selector count per contract (~64) to keep fork load reasonable.

Expected impact: closes the existing **MISSED_DRAIN_SHAPE / 18 contracts / $14k** cluster.

#### 1.4 · Loosen reentrancy detection ★★★★
26/3,613 is impossibly low. Audit the `flows_all` constraint of `reentrancy.classic_mutex_absent`; allow weaker witness (e.g. `external_call_before_state_write` without requiring full mutex-absence proof).

Expected impact: **26 → 100–400** new findings, most with clear drain paths.

## 5 · Decision log (so next session understands the trade-offs)

- **RSS cap raised 2 GB → 8 GB rather than fixing the Go auditor.** The auditor's symbolic executor scales superlinearly with CFG size; properly streaming the CFG to disk is a multi-week change inside the Go repo. The 8 GB workaround is correct for now (host has 16+ GB; auditor is single-threaded).
- **Owner-side rescue removed (v5).** Per the policy shift earlier in the session, rescues are attacker-side only. Owner-impersonation via `anvil_impersonateAccount` is no longer in the v9 drain plan. Resurrect only if we adopt a custodial / signed-consent model.
- **`buildEvidenceAdminFanout` over a generic bytecode-selector fanout (v9).** Cheaper first cut. Item 1.3 in this roadmap extends it.
- **Flashloan envelope pre-flight (broadcaster.ts).** Instead of per-step fork checks (which Aave rejects with `address(0)` as the asset), we now simulate the entire `executeRescue()` call against a forked Aave Pool. WBNB resolved automatically from a `WRAPPED_NATIVE_BY_CHAIN_BROADCASTER` map.
- **Why no new TP rescues in the v9 backfill** despite the 3.2× runtime speedup: every remaining gap requires a *new* drain shape (approval-drain, selector-fanout) or *new* detection (proxy-upgrade, reentrancy widening). Tier-1 items address both.

### 6.1 · OOM root cause (stacksim.go:565-574) ★★★★★

```503:614:go/internal/decon/stacksim/sim.go
func binop(a, b Value, sym string, fn func(x, y *big.Int) *big.Int, wrap bool) Value {
	if a.IsConst() && b.IsConst() {
		r := fn(a.Const, b.Const)
		if wrap {
			r = wrap256(r)
		}
		return Const(r, 0)
	}
	return Expr(fmt.Sprintf("(%s %s %s)", a, sym, b), 0)
}
```

Every non-const op nests the operand strings: `"(a + b)"` → `"((a + b) * c)"` → `"(((a + b) * c) - d)"`. Each level roughly doubles the string. In Uniswap V3's `mulDiv` and tick-math libraries a single symbolic value chains through 20-30 ops → `12 × 2^30 ≈ 12 GB` strings. That's the literal 4-6 GB peak we observed on 200 audits.

**Fix** (~15 LOC):
```go
// In stacksim.go, change Expr construction:
const maxExprLen = 1024
func Expr(s string, off int) Value {
    if len(s) > maxExprLen {
        h := crc32.ChecksumIEEE([]byte(s))
        s = fmt.Sprintf("<sym:%08x>", h)
    }
    return Value{Kind: ValueExpr, ExprStr: s, SourceOffset: off}
}
```
Caps per-Value memory at ~1 KB; hash preserves expression identity for equality checks downstream. After this, **revert `bin/evm-audit-capped.sh` back to 2 GB** — the legitimate maximum should be under 500 MB.

Also worth: cap `tr.StackAnnotations[off]` and `tr.Operations[].Description` lengths the same way (lines 91, 105-106, etc.).

### 6.2 · Why `proxy.upgradeTo_unprotected` finds 0 contracts (knownbc.go:521-523) ★★★★★

`knownbc.go` correctly detects the upgrade selectors and emits the right tags:

```464:535:go/internal/decon/knownbc/knownbc.go
	if r.HasERC1967ImplSlot {
		add("ERC1967_PROXY", "ERC-1967")
	}
	if r.HasERC1967AdminSlot {
		add("ERC1967_ADMIN_SLOT", "proxy_admin_guard")
	}
	...
	if r.HasERC1967AdminSlot && r.HasProxyForwarding {
		add("admin_guarded_function", "ADMIN_GUARD")   // ← BUG
	}
	if r.HasReentrancyGuardConstants {
		add("REENTRANCY_GUARD", "reentrancy_guard", "mutex_lock", "OZ_REENTRANCY_GUARD")
	}
	if r.HasInitializerPattern {
		add("INITIALIZABLE", "initializer_guard")
	}
	if len(r.ProxySelectorsFound) > 0 {
		add("PROXY_UPGRADE_SELECTORS")
	}
```

The `admin_guarded_function` + `ADMIN_GUARD` emission on **mere presence of the admin storage slot** is the bug. The detector rule `proxy.unprotected_implementation_upgrade` has both of those in its `counter_evidence.suppress_if_any` list — so any ERC-1967 proxy (which by definition has the admin slot set) gets the rule suppressed before it can fire.

**Fix has two parts**:

| File | Change |
|---|---|
| `go/internal/decon/knownbc/knownbc.go:521-523` | Don't emit `ADMIN_GUARD` from slot presence. Emit only `ERC1967_ADMIN_SLOT` (which is descriptive, not a guard claim). |
| `rules/core/proxy.unprotected_implementation_upgrade.json` | Drop `ADMIN_GUARD`, `admin_guarded_function` from `suppress_if_any`. Keep the strong-guard tokens (`STRONG_AUTH_GUARD`, `TWO_STEP_UPGRADE`, `OZ_OWNABLE2STEP`, `OZ_ACCESS_CONTROL`, `OZ_TIMELOCK_CONTROLLER`). Lower `min_role_confidence: 0.9 → 0.7`. |

Better but more work: ship a state-model-aware guard check in `state_model.go` that walks the upgrade function's `body_blocks` and only adds `ADMIN_GUARD` if a `CALLER == storage[adminSlot]` SLOAD-EQ-CALLER sequence is witnessed. Until then, the suppressor-trim is the right move.

Predicted impact in the existing corpus: **0 → 50-200 findings** with clear init-takeover-then-drain paths.

### 6.3 · Runner-side blind spot (`runner/src/proxy.ts:160-168`)

`resolveProxy()` only flags `detected: true` if `eth_getStorageAt` on the impl slot returns non-zero. **Implementation contracts** (the logic contract that lives behind the proxy — which is what actually holds the vulnerable `upgradeTo` code in UUPS) never have impl-slot storage set on their own deployments, so they get `detected: false, status: "unresolved_safe"`.

```160:168:runner/src/proxy.ts
  return {
    detected: false,
    status: "unresolved_safe",
    implementationResolved: false,
    hints: {
      source: "runner-rpc",
      delegatecallOpcodePresent,
    },
  };
```

**Fix** (≤20 LOC): bytecode fallback before this return. If runtime contains the EIP-1967 slot constant as a PUSH32, or contains `upgradeTo` / `upgradeToAndCall` selectors, mark `detected: true, proxyType: "erc1967_bytecode_evidence"`. This unblocks every implementation contract from being mis-classified `unresolved_safe`.

### 6.4 · Reentrancy + initializer rules (haven't audited yet)

Suspected to have the same shape of over-aggressive suppressor as the proxy rule. Need to read `rules/core/reentrancy.classic_mutex_absent.json` and `rules/core/init.public_initializer_takeover.json` and apply the same audit. Empirically:
- reentrancy.classic_mutex_absent: **26 / 3,613** findings (impossibly low; OZ ReentrancyGuard fires the suppressor)
- init.public_initializer_takeover: **0 / 3,613** findings

Both have the bytecode detection working (`HasReentrancyGuardConstants`, `HasInitializerPattern`) but the consume side likely filters them out.

### 6.5 · Other Go-side opportunities (no bug, just unused potential)

- `knownbc.ProxySelectorsFound` lists exactly which upgrade selectors are PUSHed. We don't expose this through the IR yet — it should be in a new `state_model.upgrade_index` parallel to `initializer_index`.
- `state_model.go:569-592` (`initializerIndex`) already has a bytecode-only fallback when storage modeling fails. Add a `upgradeIndex` with the same fallback pattern.
- `cfg.go` is fine. `Analyze()` is bounded. Don't waste time here.
- `engine.go:60-84` (`evaluateRule`) consumes `state_model.path_index` and `state_model.call_index` — both built in `state_model.go`. To add new rule semantics for the upgrade path we need to extend these indices rather than touch the matcher.
