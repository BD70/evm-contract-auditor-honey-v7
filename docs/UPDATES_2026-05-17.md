## 0. TL;DR

The simulation subsystem was upgraded end-to-end. The headline outcomes:

- **New bug class detected: permissionless AMM action** (`economic.unguarded_amm_action`).
  Catches the GPC/MSC-family (router-swap drain) AND the Movie Token / KP3R-family
  (deflationary-burn + `pair.sync()` reserve collapse). Previously undetectable.
- **New verifier engine**: `anvil-fork-economic@2` (dynamic AMM-call trace walking +
  static AMM-pattern bytecode scan).
- **Sidecar verification**: every contract processed by the worker AND every
  manual audit now also runs the economic-attack verifier and materialises a
  `critical` finding (`source=sidecar-economic-attack`) when applicable.
- **Manual audits surface the sidecar finding inline**. `/api/audits/[runId]`
  awaits the sidecar before marking the run `done` and also surfaces
  pre-existing sidecar findings keyed by `bytecode_hash` so re-uploads of the
  same bytecode show the verdict immediately.
- **Regression corpus** (`panel/src/server/sim/__corpus__/`). 21 cases — 19
  real-world TPs + 2 TN anchors — runs in ~15s and passes 21/21 in both
  default and `SIM_FEATURE_STATEDIFF=true` modes.
- **State-diff witness** (`panel/src/server/sim/state-diff.ts`). Concrete
  before/after evidence of value movement; wired into `arbitrary-call@13`.
- **Other verifier upgrades**:
  `anvil-fork-probe` bumped to `@13`; `anvil-fork-selfdestruct@3` (EIP-6780/Cancun);
  `anvil-fork-initialize@3` (owner readback assertion).
- **Stability**: panel `EMFILE` crash fixed via async `ingest-watcher` +
  PM2 ecosystem with raised ulimit.

## 1. New bug class: permissionless economic action

### 1.1 The two motivating real-world false negatives

| Victim | Chain | Loss | Class | Static pre-existing flag(s) | Real bug | Old verdict | New verdict |
|---|---|---|---|---|---|---|---|
| `0x91334d03…aeb1` (GPC/MSC) | BSC | ~150 WBNB | Permissionless function calls router swap | `arbitrary-call`, `calldataload-target`, `reentrancy` | `releaseReward(uint256)` is unguarded and routes funds through Pancake. Flash-loan sandwich drains the pool. | all `not_exploitable` (rules don't match the real bug) | `economic.unguarded_amm_action` → **VERIFIED**, attackerKind=any, critical |
| `0xb32979f3…4c18` (Movie Token / MT) | BSC | ~$242K | Deflationary-burn + flash-swap callback + `pair.sync()` reserve collapse | same 3 rules as above | Anyone can call `distributeDailyRewards` → `_executePendingBurn` → burns from pair + `pair.sync()`. Attacker arbitrages collapsed reserves. | all `not_exploitable` | `economic.unguarded_amm_action` → **VERIFIED** (`signatureKind=pair-direct`) |

Both bugs share one signature: an unguarded entry point that reaches an AMM
primitive. The static analyzer flagged the wrong rule on both contracts —
those rule firings are *correct* TNs (the bytecode does pattern-match
arbitrary-call, but the actual exploit primitive is economic), so we do NOT
loosen the existing rules. Instead we added a separate, more specific
detector and ensured both rule paths coexist.

### 1.2 The verifier — `anvil-fork-economic@2`

`panel/src/server/sim/exploits/economic-attack.ts` (new). Pipeline:

1. Pull runtime bytecode for the target contract from the live RPC fork.
2. Run `decon` to enumerate dispatched selectors and identify admin/safe
   functions (filtered out — they're never the attacker entry).
3. Resolve unresolved selectors via openchain.xyz / 4byte.directory (cached).
4. For each candidate function, build calldata with `uintFiller` (0, 1, 1e18 wei,
   …) to bypass `require(amount > 0)` guards and a multi-position address
   probe; replay each variant on the fork.
5. Walk the call trace with `amm-detect.ts`. AMM hit → **VERIFIED**.
6. If no dynamic hit, fall back to `amm-static-scan.ts`. Match → **VERIFIED
   (static evidence)**.

### 1.3 Two AMM-signature detection paths

`panel/src/server/sim/amm-detect.ts` (new) — dynamic trace walker. Recognised
selectors:
- UniV2 swap family (router): `swapExactTokensForTokens`,
  `swapExactETHForTokens`, `swapExactTokensForETHSupportingFeeOnTransferTokens`,
  etc.
- UniV3 router: `exactInputSingle`, `exactInput`, `exactOutputSingle`
  (router and router02 variants).
- Curve: `exchange(int128,…)`, `exchange(uint256,…)`.
- Balancer V2: `swap`, `batchSwap`.
- **UniV2-Pair-direct primitives** (new this session — see §1.4):
  `swap(uint,uint,address,bytes)`, `sync()`, `skim(address)`,
  `burn(address)` (pair-LP redeem), `mint(address)` (pair-LP issue).

`panel/src/server/sim/amm-static-scan.ts` (new) — bytecode scanner. Two
firing paths returned as a `signatureKind` taxonomy:

| `signatureKind` | Trigger | Bug family |
|---|---|---|
| `router+swap` | Hardcoded router `PUSH20` **AND** a PUSHed swap selector | GPC/MSC / BurgerSwap permissionless-swap |
| `pair-direct` | A PUSHed `sync` / `skim` / pair-`burn` / pair-`mint` selector (no router required) | Movie Token / KP3R / deflationary-burn |
| `both`        | Both paths firing | highest-risk shape |
| `none`        | Neither | verifier abstains on static evidence |

The pair-direct path is high precision because legitimate uses of those
selectors are tiny — basically Uniswap's own router and MEV bots. A token
or reward contract embedding `PUSH4 0xfff6cae9` (sync) is almost always
intentionally manipulating pair reserves; that's the root primitive of the
deflationary-burn class.

### 1.4 New static rule

`rules/core/access.public_economic_action_unguarded.json` (new). Severity
`critical`. Matches functions with `SWAP_OR_LIQUIDITY_PATTERN` + asset
transfer effects + no authorisation. Note: the upstream `evm-audit` static
analyzer doesn't always fire this on the deflationary-burn class because of
internal facts not being emitted; the **sidecar verifier covers that gap**
so a finding is materialised even when the static rule doesn't fire.

## 2. Sidecar verification

`runEconomicSidecar(args)` exported from
`panel/src/server/sim/worker.ts`. Idempotent per `(chain, address, rule)`.
Two callers:

1. **Background worker** — after each primary verification in
   `SimWorker.handleGroup`.
2. **On-demand re-simulate** —
   `panel/app/api/simulation/route.ts` POST handler invokes the sidecar
   after the primary verifier returns, then surfaces the result in the
   `sidecar: { ran, status, findingId, cached }` field of the response.
3. **Manual audit pipeline** — `panel/src/server/audit-service.ts`
   awaits the sidecar (capped at `SIM_SIDECAR_MANUAL_TIMEOUT_MS`, default
   25_000 ms) before marking the audit row `done`. The sidecar finding is
   linked to the manual run's `run_id`, so it surfaces in the same audit
   detail view as the static-analyzer findings.

When a sidecar finding is materialised:
- `source = sidecar-economic-attack`
- `severity = critical`
- `confidence = 0.85` (any-caller) / `0.65` (owner-only)
- `simulation_engine = anvil-fork-economic@2`
- Title varies by `signatureKind`:
  - `router+swap` → *"Permissionless function triggers AMM swap — flash-loan exploitable"*
  - `pair-direct` → *"Permissionless pair-direct manipulation (sync/skim/burn) — deflationary-burn / flash-loan exploitable"*
  - `both` → *"Permissionless function with router swap AND pair-direct manipulation — flash-loan exploitable"*
- Idempotent re-link: if a sidecar finding already exists with
  `run_id IS NULL`, the next manual audit's `run_id` is backfilled.

### 2.1 Manual-audit detail surface

`panel/app/api/audits/[runId]/route.ts` now returns:
1. Findings keyed by `run_id` (as before).
2. **PLUS** every `source LIKE 'sidecar-%'` finding whose
   `bytecode_hash` or `(contract_address, chain_id)` matches the audit
   row, deduplicated. Exposed via `sidecarExtrasCount` on the response.

This is the fix for the bug where re-uploading the same bytecode rendered
only the 3 static findings even though the system HAD detected the
economic-attack — the sidecar finding was bytecode-keyed and lived under a
different `run_id`.

## 3. Other verifier upgrades

### 3.1 `anvil-fork-probe@13` (arbitrary-call)

`panel/src/server/sim/exploits/arbitrary-call.ts`. Cumulative hardening:
- **Owner classification & impersonation**. EOA / multisig / timelock /
  renounced. Owner-only exploitable findings get `attackerKind=owner` and
  are reported as `exploitable` (not `inconclusive`) so the UI can
  distinguish them from any-caller exploits.
- **OZ v5 custom-error decoding**. `isAuthRevert` recognises
  `OwnableUnauthorizedAccount` and friends.
- **Multi-address probe**. Probe address simultaneously placed at every
  address argument position.
- **Re-entering probe** at `0x…fEEd` (31-byte custom bytecode that records
  caller + attempts re-entry with stored selector).
- **`tx.origin` forwarder probe** at `0x…F09F` (20-byte bytecode that
  forwards calls so the verifier can distinguish `msg.sender` from
  `tx.origin`).
- **`uintFiller`**. Non-probe uint args populated with non-zero defaults
  (0, 1, 1e18 wei, MAX) to bypass `require(amount > 0)` style guards.
- **State-diff witness** integrated as additive evidence
  (`SIM_FEATURE_STATEDIFF=true`).
- **Unchecked-call detection** — inner CALL fail not propagated to
  top-level is tracked.

### 3.2 `anvil-fork-selfdestruct@3`

EIP-6780 (Cancun) aware. Code-not-removed-on-selfdestruct semantics on
post-Cancun chains no longer cause false negatives.

### 3.3 `anvil-fork-initialize@3`

`owner()` readback assertion. After invoking `initialize(...)` the verifier
reads the owner storage slot and confirms the takeover took effect. Defeats
contracts where the initializer silently no-ops.

### 3.4 `anvil-fork-economic@2`

Already documented in §1.

## 4. State-diff witness

`panel/src/server/sim/state-diff.ts` (new). Captures snapshots of:
- Native (ETH/BNB) balance of attacker + extra holders.
- ERC-20 balances for a candidate set of tokens.
- Raw storage slots of interest.

Diffs them across an attempt to produce a concrete *"the attacker
received N units of X from the contract"* witness. Feature-flagged via
`SIM_FEATURE_STATEDIFF=true`.

Critical fix during the session: `extraAttackerHolders` so balance
changes accruing to the `PROBE_ADDRESS` are also counted — without this,
some real positives looked like "no favourable state change" because the
funds had moved to the probe contract, not the EOA attacker.

## 5. Regression corpus

`panel/src/server/sim/__corpus__/` (new).

- `cases.json` — 21 cases. Each case pins: chain, address, rule_id,
  expected verdict (`status`, optional `attackerKind`, optional
  `verdictContains`), tags, notes.
- `runner.ts` — runs cases in parallel, prints PASS/FAIL with a focused
  evidence summary (attacker kind, signature resolution, candidate
  count, AMM hits, static scan).
- `npm run sim:corpus` → ~13–18s end-to-end with concurrency 2.
- Flags: `--only=<id>`, `--evidence` to print the focused evidence per
  case.

| ID | Rule | Why |
|---|---|---|
| `econ-bsc-91334d03-amm` | `economic.unguarded_amm_action` | The GPC/MSC drain. Verifier must return `verified` + `attackerKind=any`. Founding case of the economic-attack verifier. |
| `econ-bsc-91334d03-arbcall-stays-tn` | `call.arbitrary_external_call_unvalidated_target` | The static analyzer matches this rule on the GPC/MSC contract too, but `releaseReward` doesn't take a caller-supplied call target. Verifier must return `not_exploitable`. Anchor against "loosening the rule to fix the FN". |

## 6. Stability & infra

### 6.1 EMFILE crash fix

`panel/ecosystem.config.cjs` (new). PM2 ecosystem that wraps `next start`
with `ulimit -n 65536`. Resolved the macOS soft-FD-limit crash loop the
panel was hitting with Next.js watchers + Anvil + SQLite all open at once.

### 6.2 Ingest watcher

`panel/src/server/ingest-watcher.ts`. Refactored to async I/O and to
yield to the event loop between batches. Removed the synchronous-stat
storm that contributed to the FD exhaustion.

### 6.3 Findings DB schema (no migrations — already present)

Sidecar findings reuse existing columns:
- `source` = `sidecar-economic-attack`
- `simulation_engine` = `anvil-fork-economic@2`
- `bytecode_hash` keyed for idempotency

## 11. What's NOT done (intentionally)

- **Auto-rescue / auto-refund pipeline** — discussed; out of scope for this
  session. The economic-attack verifier is the prerequisite primitive (it
  classifies what's drainable, by whom, with what evidence); auto-rescue
  needs a separate signer / private-tx subsystem.
- **AMM-pair burn-from-pair detector at the static-analyzer level** — the
  upstream `evm-audit` Go binary still doesn't emit the
  `SWAP_OR_LIQUIDITY_PATTERN` fact for the MT bytecode. The sidecar
  verifier covers that gap; pushing the detection into the Go analyzer is
  follow-up work.
